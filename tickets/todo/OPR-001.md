## Done when
The Security section notes that the review token can submit approving reviews,
and what that means for branch protection.

## Why
`ORG_REVIEW_TOKEN` needs Pull requests `write` to post reviews at all. That
permission also covers *submitting* them, including approvals.

For anyone whose branch protection requires an approving review before merge,
the reviewer can satisfy that gate. Irrelevant to a solo user; material to a
team using approvals as the merge control.

The section already explains that Contents stays on `read` and why. This is the
matching caveat for the permission that cannot be reduced.

## Notes
There is no finer-grained option — GitHub does not offer "comment on pull
requests but do not approve them". So this is documentation, not a fix.
